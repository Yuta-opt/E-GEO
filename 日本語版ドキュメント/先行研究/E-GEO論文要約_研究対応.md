# E-GEO論文要約と日本語TOEIC実験への対応

## 1. 論文情報

- **題名**: E-GEO: A Testbed for Generative Engine Optimization in E-Commerce
- **著者**: Puneet S. Bagga, Vivek F. Farias, Tamar Korkotashvili, Tianyi Peng, Yuhang Wu
- **版**: arXiv v2, 2026年7月14日
- **arXiv**: 2511.20867
- **原論文PDF**: `E-GEOv2_20260714.pdf`

## 2. 一言でいうと

商品説明だけを書き換えたときに、ChatGPTなどのLLMが作る商品おすすめ順位がどれだけ上がるかを測り、効果的な書き換え方を自動で発見する研究である。

## 3. 研究の中心となる問い

> 商品の事実を変えずに商品説明を改善すると、複数のLLMによるおすすめ順位を上げられるか。

従来のGEO研究では、引用の追加、権威的な文体、FAQ形式などの経験則が中心だった。E-GEOは、EC商品では順位が1位から10位として直接観測できることを利用し、GEOを明確な最適化問題として扱う。

## 4. 実験の基本構造

1. 購入相談のクエリを用意する
2. クエリごとに候補商品10件を固定する
3. その中の対象商品1件を決める
4. 元の商品説明でLLMに1位から10位まで順位付けさせる
5. Rewriterが対象商品の説明だけを書き換える
6. 同じクエリ・同じ候補10件・同じ提示順で再度順位付けさせる
7. 対象商品の順位差を計算する

```text
順位改善量 = 書き換え前の順位 - 書き換え後の順位
```

例として、7位から3位になれば順位改善量は `+4` である。

重要な点は、**Rewriterには評価クエリを渡さない**ことである。販売者は将来どのような検索・相談が行われるか分からないため、特定クエリ向けではなく、多様な購入意図に効く汎用的な商品説明を目指す。

## 5. データセット

- 長文・会話形式の購入クエリ: **13,747件**
- クエリごとの候補商品: **10件**
- 商品コーパス: Amazon Reviews 2023の約1,704万商品
- 固定Test: **2,000クエリ**
- クエリ源: Redditの `r/BuyItForLife`

短いキーワード検索ではなく、予算、用途、過去の不満、好み、制約などを含む長文の購入相談を使用する。候補10件は検索段階で固定し、研究では検索後の**再ランキング段階**だけを評価する。

## 6. 使用モデル

### Re-ranker（順位を付けるモデル）

- GPT-5
- Claude Sonnet 4.5
- Gemini 3 Flash Preview
- DeepSeek V3.2
- Llama 4 Maverick

### Rewriter（商品説明を書き換えるモデル）

- GPT-5
- Claude Sonnet 4.5
- Gemini 3 Flash Preview
- GPT-4o-mini
- GPT-4.1
- DeepSeek V3.2
- Llama 4 Maverick

RewriterとRe-rankerは別の役割として分ける。

## 7. 主な実験結果

### 7.1 単純な一文指示でもモデル差が大きい

共通の単純な指示で商品説明をリライトしたところ、GPT-5とClaudeは平均順位を比較的安定して改善した。一方、GPT-4o-miniは全Re-rankerで平均的に順位を悪化させた。

つまり、**どのLLMに書かせるかだけでも結果が大きく変わる**。

### 7.2 長く書けば順位が上がるわけではない

商品説明の文字数増加と順位改善の相関はほぼ0だった。箇条書きには小さな正の効果があったが、文字数と箇条書きだけでは順位改善の差をほとんど説明できなかった。

したがって、元データを商品説明の文字数で先に強く絞ると、文字数の影響を正しく分析できなくなる可能性がある。

### 7.3 人が考えたGEOテクニックは多くの場合うまくいかない

15種類の手作りプロンプトを比較したところ、単純な指示を明確に上回ったものは少なかった。広告調、外国語表現、極端な短文化、ストーリー形式などは順位を大幅に悪化させた。

手作業で「良さそうな書き方」を考えるだけでは、逆効果になることがある。

### 7.4 プロンプトの自動最適化は多くの条件を改善した

GPT-4.1をRewriterとして固定し、複数Re-rankerの結果をMeta-optimizerに見せ、リライト指示を反復改善した。

- 最適化前後の75セル中、**63セルで改善**
- 55セルで `+0.10` 以上改善
- 特に `unique` と `competitive` を初期値にした最適化プロンプトは、5モデルすべてで正の順位改善を示した

初期プロンプトが悪くても、自動最適化によって大きく回復できることが示された。

## 8. 発見された「共通して効く書き方」

異なる15種類の初期プロンプトから始めても、最適化後は次の特徴へ収束した。

- 検索・ランキングで評価されることを意識する
- 購入者の意図や利用場面を想定する
- 関連キーワードと同義語を自然に含める
- 冒頭に商品目的と主要メリットの要約を置く
- 見出しを使う
- 短い段落や箇条書きで読みやすくする
- 具体的な用途を示す
- よくある質問に答える
- キーワードを不自然に詰め込まない
- 元の商品説明にない事実を追加しない

論文では、これをクエリ・商品・モデルをまたいで機能する可能性がある**普遍的なリライト戦略**としている。

## 9. 不正操作への対策

Re-rankerの指示に、誇張、虚偽、ランキング操作命令などを含む商品を下位にし、`questionable_products`として記録する一文を追加した。

14種類の攻撃的プロンプトを試すと、露骨な操作ほど検出され、順位を上げにくかった。さらに「検出されずに順位を上げる」ようMeta-optimizerへ指示しても、最終的なプロンプトは誇張を避け、事実に基づく中立的な文章へ収束した。

この結果から、単純な防御指示の下では、順位改善は不正操作よりも内容の実質的改善によって生じる可能性が高いと論じている。

## 10. 原論文の限界

- 英語だけを対象としている
- Reddit `r/BuyItForLife` の利用者層・耐久財への偏りがある
- Amazon Reviews 2023の商品説明だけを使用している
- 候補商品の検索方法と初期Re-rankerの偏りを引き継ぐ
- 画像、動画、属性表などのマルチモーダル情報を扱っていない
- Meta-optimizerは比較的単純で、より高度な最適化方法には未検証の余地がある
- 不正操作への防御は最低限の一文だけであり、実運用では外部分類器やモデレーションとの併用が必要

## 11. 日本語TOEIC実験との対応

本研究は、原論文の「英語・複数商品カテゴリ」を、次のように転移して検証する。

| 原論文E-GEO | 日本語TOEIC実験 |
|---|---|
| 英語 | 日本語 |
| Amazonの複数カテゴリ | 楽天ブックスのTOEIC教材 |
| Reddit由来の長文相談 | 短文検索＋対応する長文相談 |
| 1クエリ10商品 | 同じく候補10商品 |
| 対象商品1件だけを書き換える | 同じ |
| 平均順位改善量 | 同じ |
| 複数Re-ranker | 同じ方針 |
| 英語で最適化したプロンプト | 英語原文・日本語翻訳・日本語適応を比較 |

### 主な研究問い

1. 英語で得られたE-GEOのリライト戦略は、日本語のTOEIC教材でも順位改善に有効か
2. 英語プロンプトをそのまま使う場合、日本語へ翻訳する場合、日本語向けに調整する場合で結果は変わるか
3. 同じ購入意図でも、短い検索キーワードと自然な長文相談でリライト効果は変わるか
4. 商品説明の元の文字数によって順位改善効果は変わるか

## 12. 日本語実験で固定すべき重要事項

- クエリ、候補10件、対象商品、提示順を条件間で固定する
- Rewriterには原則として評価クエリを渡さない
- 元説明にない対象スコア、機能、特典、実績を追加しない
- Testデータをプロンプト作成・選択に使用しない
- 元の商品説明の文字数は除外条件ではなく、分析変数として保存する
- 元順位とリライト後順位を同じRe-ranker設定で取得する
- APIモデル名、バージョン、temperature、実行日、トークン数、費用、失敗回数を保存する
- 同じリライト結果と元順位はキャッシュし、再利用する
