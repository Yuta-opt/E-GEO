## 2. 研究の目的

英語版E-GEOでは、商品検索結果に含まれる対象商品の説明文だけを書き換え、同じ検索クエリと同じ候補商品集合の中で、対象商品の順位がどの程度変化するかを評価します。

本研究では、日本語のTOEIC教材を対象として、次の問いを検証します。

### 主研究

> 英語で得られたE-GEOの汎用的な商品説明リライト戦略は、日本語の商品検索でも順位改善に有効か。

### 追加検証

> 同じ購入意図について、短い検索キーワードと自然な長文の購入相談では、商品説明リライトの効果が異なるか。

実験では、候補商品10件のうち対象商品1件の説明文だけを書き換えます。商品名、候補商品、候補順、検索クエリ、Re-rankerの設定は条件間で固定します。

## 5. 最初に検討したESCIデータと方針転換

### 5.1 当初の案

当初は、Amazon Scienceが公開するShopping Queries Datasetの日本語部分を用いる案を検討しました。

ESCIには検索クエリ、商品候補、関連度ラベルがあるため、検索実験を構築しやすい利点がありました。

### 5.2 実際に確認して分かった問題

- クエリが短いキーワード中心だった
- 日本語以外の商品や表記ノイズが混ざっていた
- TOEIC教材という一貫した商品領域を作りにくかった
- 本研究の「日本語の自然な購入相談」という追加検証に合わせにくかった

### 5.3 最終判断

ESCIを主データとして使う案は中止し、楽天ブックスから収集したTOEIC教材へ移行しました。

ESCI関連のコード、データ、`pyarrow`依存関係、`.gitignore`設定は削除しました。

この方針転換によって、商品領域をTOEIC教材に限定し、短文と長文の購入意図を人間が確認できる設計へ変更しました。

## 6. 楽天ブックスからの商品収集

### 6.1 収集方法

Octoparseを使用し、楽天ブックスの「TOEIC」検索結果から10ページ、合計300商品を取得しました。

1ページあたり約30件の商品が表示される構成でした。

ワークフローは概ね次の構造です。

```text
Webページを開く
└─ ページ送りループ
   ├─ 商品一覧ループ
   │  ├─ 一覧ページの基本情報を収集
   │  ├─ 商品詳細ページを開く
   │  └─ 商品説明を収集
   └─ 次のページへ移動
```

### 6.2 取得項目

```text
title_raw
product_url
image_url
isbn_raw
author
publication_info_raw
price_raw
description
```

### 6.3 収集しなかった項目

次の情報は、人気度や販売実績による漏洩を避けるため、実験入力に使用しません。

- レビュー数
- 評価点
- ランキング
- ポイント
- 在庫表示
- 配送表示
- 販売数

### 6.4 商品説明取得用XPath

商品詳細ページの「内容紹介」を取得するため、次のXPathを使用しました。

```xpath
(
  //*[starts-with(normalize-space(.),'内容紹介')
      and string-length(normalize-space(.)) > 30
      and not(.//*[starts-with(normalize-space(.),'内容紹介')
                  and string-length(normalize-space(.)) > 30])]
  |
  //*[starts-with(normalize-space(.),'内容紹介')
      and string-length(normalize-space(.)) <= 30]
      /following-sibling::*[normalize-space()][1]
)[1]
```

### 6.5 元データの保存場所

```text
日本語版データ/TOEIC/元データ/rakuten_toeic_raw_20260727.xlsx
```

元Excelは直接編集せず、再処理のための原本として保持します。

## 13. 短文・長文クエリの作成ルール

### 13.1 短文クエリ

- 3〜8語程度を目安にする
- 実際の検索キーワードとして自然にする
- 対象商品の固有名詞を原則入れない
- 目標スコア、分野、弱点、教材形式など重要条件だけを書く

例：

```text
TOEIC 600点 初心者 総合対策
```

### 13.2 長文クエリ

- 短文と同じ購入意図を2〜3文で具体化する
- 現在スコア、目標、弱点、学習期間、希望する教材形式など必要な条件を書く
- 短文に存在しない重要条件を勝手に追加しない
- 対象商品が変わるほど意図を変更しない

例：

```text
現在のスコアが450点前後で、まず600点を目指しています。
単語だけではなく、リスニングとリーディングを一冊で基礎から学べる教材を探しています。
```

### 13.3 対象商品を選んだ理由

商品説明に書かれている事実だけを使い、その商品が購入意図に最も合う理由を1〜2文で記録します。

商品説明にない特典、対象スコア、実績、機能を推測で追加してはいけません。

## 14. データ分割と漏洩防止

購入意図80件を次のように分割します。

```text
Train：40件
Validation：10件
Test：30件
```

守るルールは次のとおりです。

- 分割は購入意図単位で行う
- Testの購入意図はプロンプト作成や選択に使用しない
- Testの対象商品をTrain・Validationの対象商品にしない
- 可能な限りTest対象商品をTrain・Validationの候補集合にも入れない
- 候補商品は複数の購入意図で再利用してよい
- 対象商品80件は重複させない
- 乱数シードと完成ファイルを固定する

商品プール194件で80組×10商品の候補集合を作るため、候補商品の再利用は必要です。重要なのは、対象商品の分割漏洩を防ぐことです。

## 15. 今後の実験条件

比較する条件は次の4つです。

| 条件 | 内容 |
|---|---|
| Original | 商品説明を書き換えない |
| EN-Zero | 原版E-GEOの英語最適化プロンプトを日本語商品へ適用 |
| JA-Zero | 英語プロンプトを自然な日本語へ翻訳して適用 |
| JA-Adapted | Train・Validationを使って日本語向けに調整 |

Rewriterには、原則として評価対象の検索クエリを渡しません。

商品説明にない情報を追加することは禁止します。

## 16. 評価方法

主指標は対象商品の順位改善量です。

```text
順位改善量 = 書き換え前の順位 - 書き換え後の順位
```

例：

```text
書き換え前：7位
書き換え後：3位
順位改善量：+4
```

記録する予定の指標は次です。

- 平均順位改善量
- 順位上昇率
- 順位低下率
- 順位不変率
- 標準誤差
- モデル別結果
- 短文と長文の差
- 条件別結果
- API入力トークン
- API出力トークン
- 推定API費用
- 失敗回数と再実行回数

## 17. API予算管理

研究全体のAPI予算上限は100ドルです。

- 先に少数件のパイロットを実施する

## 20. 方法上の注意点

### 20.1 楽天検索順位を正解ラベルにしない

楽天ブックスの検索表示順には、人気度、売上、在庫、広告、検索最適化などが影響している可能性があります。

そのため、楽天上の表示順位を実験の正解順位として使用しません。

### 20.2 最初の200件をそのまま使わない

検索結果の上位から単純に200件を採用すると、ベストセラーや人気商品に偏る可能性があります。

本研究では、カテゴリと品質条件を用いて商品プールを作成し、固定シードで再現できるようにしました。

### 20.3 短い商品説明を一律排除しすぎない

公式問題集などは、重要な教材であっても説明文が短い可能性があります。

そのため、クレンジング段階では短い説明を即座にすべて除外せず、商品プール段階で100文字以上、対象商品段階で200文字以上という段階的な条件を採用しました。

### 20.4 対象商品と候補商品の役割を分ける

説明文が短い商品や説明文が他商品と完全一致する商品は、候補商品としては使用できますが、書き換え対象商品には不向きです。

そのため、`target_eligible_final`で対象商品としての利用可否を別管理します。

## 21. ポスター・論文の方法節に使える要約

本研究では、楽天ブックスの「TOEIC」検索結果から公開商品情報300件を収集した。電子書籍、商品説明欠損、TOEIC非関連商品を除外し、表記正規化、ISBN・価格の整形、説明文のクリーニングを行った結果、271件を採用候補とした。次に、商品説明100文字以上、価格情報あり、TOEIC L&R教材であることを条件としてカテゴリ別に一次商品プール200件を構成した。発売時期、旧形式教材、版違い、説明文重複を追加検査し、最終的に194件の商品プールと155件の対象商品候補を得た。対象商品候補から80件を抽出し、Train 40件、Validation 10件、Test 30件へ分割する。各購入意図について、意味を対応させた短文クエリと長文クエリを作成し、同一候補10商品内で対象商品の商品説明を書き換える前後の順位差を評価する。
