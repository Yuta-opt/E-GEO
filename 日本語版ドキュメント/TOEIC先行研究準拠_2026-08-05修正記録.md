# TOEIC版E-GEO 先行研究準拠修正記録

更新日：2026-08-05  
対象ブランチ：`ja-toeic-prototype`

## 結論

TOEIC版は、E-GEO v2の完全な同規模再現ではなく、次の位置付けとする。

> **先行研究の中核アルゴリズムを維持した日本語・小規模再現 ＋ 短文クエリへの転移評価**

維持する条件：

- 初期プロンプト：15種類
- Train / Validation / Test：40 / 10 / 30
- 2 epochs
- 1 epochあたり4 batches
- batch size 10
- 各初期プロンプトの評価版：8版
- Meta-optimizer更新：各epochの最後を除くため6回
- 学習Re-ranker：GPT-4.1、Gemini
- 最終Test：GPT-5、Gemini、Claude
- 最適化は長文クエリのみ
- 短文はプロンプト固定後の追加評価のみ

## 修正した重大点

### 1. Validation漏洩の除去

E-GEO v2 Algorithm 1では、Meta-optimizerが読む履歴 `H` に追加されるのはTrainのエンジン別結果である。Validationは各版の選択にのみ使用する。

旧実装では、履歴表示にTrain平均とValidation平均の両方が入り、その文章がMeta-optimizerへ渡っていた。

修正後：

- Meta-optimizerへ渡す履歴はTrain結果のみ
- Validation結果は保存する
- Validationは最良版選択にのみ使用する
- Testはプロンプト固定後までロックする

実装：

- `日本語版コード/05e_TOEIC先行研究準拠_OpenAI_Gemini_Claude実験.py`
- 関数 `train_only_history_text`

### 2. モデルファミリー別Re-ranker System Prompt

先行研究では、共有User Promptに加え、GPT、Gemini、Claudeなど各モデルファミリー固有のSystem Promptを使用している。

旧TOEIC実装では、全モデルへ短い共通System Promptを使用していた。

修正後は、原著コードの以下を直接読み込む。

- GPT-4.1：`get_gpt41_prompt()`
- GPT-5：`get_gpt5_prompt()`
- Gemini：`get_gemini_prompt()`
- Claude：`get_claude_prompt()`

正本：

- `src/multi_model_optimization/prompts.py`

### 3. Rewriter入力をlisting全体へ変更

原著実装では、Rewriterへ商品タイトル・特徴・説明を結合したlisting文章を渡す。

楽天TOEICデータにはAmazonと同じ特徴配列がないため、本研究では次を渡す。

- 商品名
- 商品説明

購入クエリはRewriterへ渡さず、query-blindを維持する。

リライト後は対象商品のlisting全体を置き換え、固定された他9商品と再ランキングする。

## 分析の修正

### 4. 埋め込み収束

旧分析は多言語MiniLMで初期版と最終版だけを比較していた。

先行研究準拠分析では：

- `text-embedding-3-large`
- 15プロンプトの全評価版
- 平均コサイン距離 to centroid
- 平均pairwise cosine distance

をepoch・batch情報付きで保存する。

実装：

- `日本語版コード/06b_TOEIC先行研究準拠結果分析.py`

埋め込みAPIは `--execute-embeddings` を付けた場合だけ実行する。結果はJSONLへキャッシュされる。

### 5. 10特徴を三段階の人手評価へ変更

E-GEO v2 Section 5.5.1では、次の10特徴を人間が三段階で評価している。

- Search-engine goal
- User intent
- Keywords & synonyms
- Opening summary
- Section headings
- Scannable bullets
- Use cases
- User questions (FAQ)
- No keyword stuffing
- Maintains factuality

評価値：

- 0：Absent
- 1：Implicit
- 2：Explicit

単語が含まれるかだけで判定する自動キーワード分析は、先行研究の再現結果として使用しない。

正式実験後、次の評価表が生成される。

`日本語版データ/TOEIC/06_分析結果/02_OpenAI_Gemini_Claude/04_prompt_feature_manual_review.xlsx`

`scores`シートへ0/1/2を入力し、分析を再実行すると特徴集計とheatmapが生成される。

## APIキーの扱い

### 候補10件選定

OpenAIのみで独立実行可能。

### 正式メタ最適化

GPT-4.1とGeminiの両方のTrain結果から次プロンプトを作るため、OpenAIとGeminiを同じ正式trajectory内で使用する。GPTだけで最適化した後からGeminiを足すと、別の実験になる。

### Held-out Test

設計上はプロンプト固定後にGPT-5、Gemini、Claudeを別時間に評価できる。ただし現在の標準ランナーは、事故防止のため3キーを開始前に確認して一括実行する。

## 完了状態

`07b_TOEIC先行研究準拠完了チェック.py`は、次を分けて表示する。

1. 順位数値・統計・埋め込み収束が完成
2. 10特徴の人手評価が未入力
3. 人手評価を含む全分析が完成

人手評価が未入力でも数値実験を失敗扱いにはしないが、ポスターで先行研究同等の特徴heatmapを掲載するには0/1/2評価を完了させる。
