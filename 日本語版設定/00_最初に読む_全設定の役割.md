# 00 最初に読む：日本語版設定全ファイルの役割

最終更新：2026年8月6日  
対象ブランチ：`ja-toeic-prototype`

このファイルは、`日本語版設定/`にあるJSON設定の違いと、正式実験でどれを優先するかを説明します。

## 現在の正式設定

### 研究設計

```text
TOEIC_EGEO実験設定_v3_先行研究準拠.json
```

ファイル名は互換性のため`v3`のままですが、内部`schema_version`は`toeic_egeo_meta_optimization_v4_final_safety`です。

- Train 40／Validation 10／Test 30
- 初期プロンプト15種類
- 2 epochs、4 batches、batch size 10
- 各初期プロンプト8版を評価
- Meta更新6回
- Validationは版選択専用
- Testはプロンプト固定後までロック
- 短文は固定後の追加転移評価
- 最適化長文と短文で同一リライトを共有
- 95%信頼区間とHolm補正
- 接続Smokeと候補1件Smokeを正式80件より先に要求

### 第一段階のモデル・予算

```text
TOEIC_OpenAI_Gemini実験設定_v1.json
```

- Candidate selector：GPT-5 mini、minimal reasoning、出力上限200
- Rewriter：GPT-4.1
- Meta-optimizer：GPT-4.1
- Training Model A：GPT-4.1
- Training Model B：Gemini 3.1 Flash-Lite
- Held-out Model E：GPT-5、minimal reasoning、出力上限1000
- Held-out Model F：Gemini 3.5 Flash-Lite、temperature送信なし
- OpenAI本体hard stop：98 USD
- Gemini hard stop：15 USD
- 総hard stop：113 USD

### Claude追加時

```text
TOEIC_OpenAI_Gemini_Claude実験設定_v1.json
```

OpenAI＋Gemini完了後に、同じ出力フォルダとキャッシュを使ってClaudeの最適化済み長文Testだけを追加します。

- Claude hard stop：8 USD
- 3社総hard stop：121 USD
- OpenAI・Geminiの成功済みジョブと共有リライトを再利用
- 再Train不要

## 設定ファイルの優先順位

1. 件数・分割・更新手順・統計方針：`TOEIC_EGEO実験設定_v3_先行研究準拠.json`
2. OpenAI＋Gemini先行実行：`TOEIC_OpenAI_Gemini実験設定_v1.json`
3. Claude追加：`TOEIC_OpenAI_Gemini_Claude実験設定_v1.json`
4. 先行研究由来の指示：`E_GEO先行研究_*.json`

`TOEIC_APIモデル設定_v1.json`とOpenAI単一版は、正式な提供元横断結果には使用しません。

## ファイル一覧

### `E_GEO先行研究_初期プロンプト15種.json`

先行研究で比較された15種類のリライト戦略の英語原文と忠実な日本語実装訳です。

- TOEIC固有の有利な条件を追加しない
- 各プロンプトを別々に最適化する
- `{description}`を必ず保持する

### `E_GEO先行研究_共通プロンプト設定.json`

Rewriterの共通System Promptと、候補10商品を順位付けするRe-ranker用User Promptです。

### `E_GEO先行研究_候補10件選定設定.json`

Dense Retrieval上位30商品から関連する10商品を選ぶ指示です。

- 入力：購入クエリ、番号付き候補30件
- 出力：0〜29の異なる整数10個を昇順にしたJSON配列
- 正式実行元：`04d_TOEIC候補10商品を安全に選ぶ.py`

### `E_GEO先行研究_メタ最適化設定.json`

複数モデルのTrain順位履歴から、新しいリライト指示を生成します。

- Validation結果は入力しない
- Re-ranker名はModel A／Bとして匿名化
- 一つのモデルだけへの過適合を避ける
- `{description}`を保持する

### `TOEIC_EGEO実験設定_v3_先行研究準拠.json`

正式研究設計の正本です。

- Query-blind Rewriter
- 商品名＋商品説明を入力
- Train履歴だけで更新
- Validationで版選択
- Testロック
- 長文で固定後に短文を評価
- 同じ最適化リライトを長文・短文で再利用
- Providerごとの非対称Test条件
- Gemini・Claudeの短縮System Promptを予算制約による差分として明記
- Wilcoxon、Holm、95% bootstrap CI

### `TOEIC_OpenAI_Gemini実験設定_v1.json`

現在の第一段階で使用するモデルID、sampling設定、出力上限、単価、Provider別予算、Test条件をまとめます。

重要な安全値：

```text
GPT-5 reasoning effort = minimal
GPT-5 max_output_tokens = 1000
Gemini 3.5 temperature = null
Gemini 3.5 supports_temperature = false
shared_rewrite_across_long_short = true
failed_usage_counted_before_parse = true
connectivity_smoke_before_candidate_full = true
```

### `TOEIC_OpenAI_Gemini_Claude実験設定_v1.json`

Claude追加時の最大構成です。Claudeは最適化済み長文Testだけを担当します。

3モデルで条件が異なるため、すべてを一つの平均へ混ぜません。

### `TOEIC_OpenAI単一キー実験設定_v1.json`

OpenAIだけで実験構造を確認する比較・障害切り分け用設定です。正式な提供元横断結果へ混ぜません。

### `TOEIC_APIモデル設定_v1.json`

実装途中のモデル候補を整理した中間設定です。古いモデルや予算が残る可能性があるため、正式実行には使用しません。

## Re-ranker System Promptの扱い

- OpenAI：先行研究コードのモデルファミリー別System Prompt
- Gemini：短いGemini専用商品検索Re-ranker Prompt
- Claude：短いClaude専用商品検索Re-ranker Prompt

Gemini・Claudeの短縮Promptは費用制約による差分です。全Providerで先行研究Promptを完全再現したとは報告しません。

## APIキー

```env
OPENAI_API_KEY=
GEMINI_API_KEY=
ANTHROPIC_API_KEY=
```

OpenAI＋Gemini先行実行では最初の2キーを使用します。Claudeキーは3社版の接続Smokeと追加評価時だけ必要です。

## 安易に変更しないもの

- Train／Validation／Test件数
- query-blind条件
- 同一候補10件・同一対象商品条件
- 最適化長文・短文の同一リライト条件
- Testロック
- 15種類の忠実な日本語訳
- 8評価版・6更新
- seed 42
- Train開始後のモデル構成
- Provider別hard stop
- Parser失敗分も費用へ含める規則
- Holm補正と95%信頼区間

設定を変更する場合は、Smokeまたはpilotと正式実験を分離し、出力フォルダと実施記録を分けます。
