# E-GEO 日本語転移実験ガイド

この文書は、英語版E-GEOの実験設計を土台として、日本語の商品検索におけるリライト戦略の転移性能を調べるための作業ガイドです。

コマンドは、原則としてリポジトリ直下の `E-GEO/` で実行します。

---

## 1. この研究で調べること

原版E-GEOは、対象商品の説明文だけを書き換え、同じ検索クエリ・同じ候補商品10件の中で順位がどのように変わるかを測る研究です。

本研究では、次の問いを小規模に検証します。

### 主研究

> 英語で得られたE-GEOの汎用リライト戦略は、日本語の商品検索でも順位改善に有効か。

### 追加検証

> 日本語の短い検索キーワードと、同じ検索意図を自然な日本語で詳しく書いた長文クエリでは、リライトによる順位改善効果が異なるか。

本研究では、Amazon Scienceが公開するShopping Queries Dataset（ESCI）の日本語データを使用します。ESCIには、日本語の検索クエリ、商品候補、商品名、商品説明、箇条書き、ブランド、E/S/C/I関連度ラベルが含まれます。

ESCIのクエリは短い検索キーワードが中心です。そのため、追加検証用として、一部の短文クエリを、元の検索意図を保った自然な長文クエリへ拡張します。

---

## 2. 原版E-GEOと本研究の対応

| 項目 | 原版E-GEO | 本研究 |
|---|---|---|
| 言語 | 英語 | 日本語 |
| クエリ | Reddit由来の長文購入相談 | ESCIの日本語検索クエリ＋一部を長文化 |
| 商品 | Amazon英語商品 | ESCIのAmazon日本語商品 |
| 候補商品数 | 1クエリにつき10商品 | 同じく10商品 |
| 書き換え対象 | 候補10商品のうち1商品 | 同じく1商品 |
| Rewriterへの入力 | 汎用リライト指示＋商品説明 | 同じ。評価クエリは原則渡さない |
| Re-rankerへの入力 | クエリ＋候補商品10件 | 同じ |
| 主評価指標 | 書き換え前後の平均順位改善 | 同じ |
| データ規模 | 学習1,000・検証500・テスト2,000 | 100ドル以内に縮小 |
| 追加検証 | なし | 短文クエリと長文クエリの比較 |

重要なのは、商品説明を書き換えるRewriterと、候補商品を順位付けするRe-rankerを分けることです。

```text
汎用リライトプロンプト＋対象商品説明
        ↓
Rewriterが対象商品の説明だけを書き換える
        ↓
検索クエリ＋候補商品10件
        ↓
Re-rankerが1位から10位まで順位付け
        ↓
書き換え前後の対象商品の順位差を計算
```

```powershell
uv run python "日本語版コード/05_ESCI日本語データ確認.py"
```

## 7. データ作成の暫定方針

最終件数は、06番の全体分析とAPIパイロット後に確定します。

現時点の目安は次のとおりです。

| 用途 | 暫定件数 |
|---|---:|
| Train | 80 |
| Validation | 40 |
| Test | 120 |
| 合計 | 240 |

各データは次の要素を持ちます。

```text
検索クエリ1件
＋候補商品10件
＋書き換え対象商品1件
```

追加検証では、このうち60〜80件程度について、短いESCIクエリと意味を対応させた自然な長文クエリを作成する予定です。

例：

```text
短文：
静音 ワイヤレスマウス

長文：
大学と自宅の両方で使えるワイヤレスマウスを探しています。
図書館でも使うため、クリック音が小さく、長時間使っても手が疲れにくいものを希望します。
```

短文と長文で、候補商品10件と書き換え対象商品は同じものを使用します。

## 8. 比較条件

暫定的に次の条件を比較します。

| 条件 | 内容 |
|---|---|
| Original | 商品説明を書き換えない |
| EN-Zero | 原論文の英語最適化プロンプトを日本語商品へ適用 |
| JA-Zero | 英語最適化プロンプトを自然な日本語へ翻訳して適用 |
| JA-Adapted | 少量の日本語Train・Validationデータでプロンプトを調整 |

最終Testデータは、プロンプトの作成・選択には使用しません。

追加検証では、各条件を短文クエリと長文クエリで評価します。

---

## 9. 評価指標

主指標は、原版E-GEOと同じ平均順位改善です。

```text
順位改善量 ＝ 書き換え前の順位 − 書き換え後の順位
```

例：

```text
書き換え前：7位
書き換え後：3位
順位改善量：+4
```

合わせて次も記録します。

- 平均順位改善量
- 順位が上昇したquery-productペアの割合
- 順位が低下した割合
- 標準誤差
- モデル別の結果
- 短文と長文の差
- API入力・出力トークン
- 推定API費用

## 10. API料金の管理

研究全体のAPI予算上限は100ドルです。

- 先に5〜20件のパイロットを実施する
- 各API呼び出しの入力・出力トークンを保存する
- 推定累計費用をCSVへ記録する
- 推定費用が60ドルで警告する
- 推定費用が80ドルに達したら新規API処理を停止する
- 残り20ドルは失敗時の再実行と予備に残す

`.env`に保存したAPIキーはGitHubへpushしません。

```dotenv
OPENAI_API_KEY=<自分のAPIキー>
OPENROUTER_API_KEY=<自分のAPIキー>
```

APIを使うファイルには、実行前確認と少数件モードを設けます。
